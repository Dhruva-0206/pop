## 1. Project summary
PoP: Proof of Purchase. A protected checkout for Indian Instagram/WhatsApp sellers and small websites (ETHGlobal Mumbai 2026, From Scratch).
Buyer pays the specified Whitechain test USDT into `PoPCheckout` on Whitechain Sepolia (1874), using a seller-signed EIP-712 Offer.
Funds are released only by the buyer's 6-word delivery code at the door; a missed ship-by or deliver-by deadline lets anyone `finalize` into a full refund.
Courier role can only do Shipped → Disputed; the arbiter resolves disputes and bans. After a Released order, a World ID proof gates one review per human per seller.
Reviews are readonly Arkiv entities (Rabdi 7794095), created by our attestor and transferred to the buyer; a separate "Kurta Co." store reads them with its own key.

**Judge sentences (every design choice must protect these):**
1. "If it doesn't arrive, you get your money back automatically. Nobody can stop that refund, including us."
2. "The money is released by the buyer's code at the door; our courier key can't release a single rupee."
3. "Reputation is earned only from protected deliveries, counts each human once per seller, and lives on Arkiv where any app can read it."

## 8. Blockers and decisions log
- Fri 6 Nov: **"Pay with PoP" design decisions.** (1) The merchant signs its own Offers (its seller key stays in the merchant's app; PoP never holds it); a session is a single-use listing (maxUnits 1) whose id is bound into the Offer (`listingId = keccak(sessionId)`) and whose `externalRef = keccak(merchantRef)`, so the payment on-chain carries the merchant's cart id. (2) API keys are stored as sha256 only; webhook secrets AES-256-GCM encrypted (they must be recoverable to sign); `returnUrl` must match the merchant's allowed origin. (3) Webhooks are only a hint: the SDK's `confirmOnChain` checks that the order is the merchant's, matches buyer/amount, is in a state that fits the event, and that the funding tx carries keccak(merchantRef); a pinned chain config (`CHAIN_ID`, `RPC_URL`, `CHECKOUT_ADDRESS`, `REGISTRY_ADDRESS`, `DEPLOY_BLOCK`) removes any reliance on PoP for the contract address. (4) No indexer: the dispatcher reads the checkout's events from a cursor (idempotent, `unique(merchant, order, event)`); order pages and order registration also trigger a pass, `npm run webhooks` keeps it running. Only five events are sent (funded, shipped, delivered, released, refunded); disputes/splits are not yet. (5) The demo store holds its own secrets in `apps/demo-store/.env.local` (written by `scripts/seed-merchant.ts`, gitignored) and does not read PoP's server env. (6) The store's order book is in memory (demo); every status in it was chain-confirmed so it can be rebuilt.
